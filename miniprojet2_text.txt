Phase 4 — Implémentation — Front-end, Back-end et Base de données
Étape 4.1 — Développement front-end
Approche Recommandée
Objectif : Développer la partie visible du site en intégrant dès le départ les principes d’éco-
conception web : sobriété visuelle, poids minimal des ressources, chargement rapide, etc.
Technologies recommandées : HTML5 / CSS3 natif en priorité. JavaScript minimal. Frame-
work CSS léger si justifié (ex. : TailwindCSS en mode purge, Pico.css, Classless CSS). Aucune
bibliothèque lourde sans justification explicite.

Consignes
Consignes de développement :
a) Optimisation des ressources statiques :
— Minifier les fichiers CSS et JavaScript (outils : cssnano, terser, ou pipeline Vite/Parcel
minimal).
— Compresser toutes les images avant intégration (https://squoosh.app, https://
tinypng.com).
— Préférer les formats modernes : WebP, AVIF plutôt que JPEG/PNG lourds.
— Limiter le nombre total de fichiers chargés par page (objectif : moins de 15 requêtes
HTTP par page).
b) Chargement intelligent :
— Implémenter le lazy loading sur les images et médias (loading="lazy").
— Différer le chargement des scripts non critiques (defer / async).
— Utiliser des polices système ou des polices auto-hébergées légères plutôt que Google
Fonts (1 requête externe évitée par police).
c) Sobriété visuelle :
— Pas d’animations CSS/JS sans valeur fonctionnelle.
— Mode sombre proposé si possible (réduit la consommation sur écrans OLED).
— Interface paginée plutôt que scroll infini pour les listes.
— Pas de vidéo en autoplay ni de lecture automatique de médias.
d) Accessibilité de base :
— Balises sémantiques (<main>, <nav>, <article>, <footer>).
— Attributs alt sur toutes les images.
— Contraste suffisant entre texte et fond (ratio 4,5 :1).
Concepts Clés Green IT
Indicateurs Green IT à surveiller pour le front-end :
— Poids total d’une page : viser < 500 Ko (idéalement < 200 Ko).
— Nombre de requêtes HTTP : viser < 15 par page.
— Score Lighthouse Performance : viser > 80/100.
— First Contentful Paint (FCP) : < 1,8 s.
— Largest Contentful Paint (LCP) : < 2,5 s.
Étape 4.2 — Développement back-end et accès à la base de données
Approche Recommandée
Objectif : Implémenter la logique serveur, sécurisée et sobre, avec une gestion rigoureuse des
accès aux données.
Technologies recommandées : Node.js (Express), Python (Flask ou Django minimal), PHP natif
ou Laravel léger. Base de données : SQLite (pour un projet petit), PostgreSQL ou MySQL (pour
un projet à déployer). ORM léger ou requêtes SQL directes.

Consignes
Consignes de développement :
a) Gestion des utilisateurs — CRUD complet obligatoire :
— Création : formulaire d’inscription avec validation côté serveur (hash du mot de passe,
vérification du format email).
— Lecture : liste paginée des utilisateurs (max. 20 résultats par page).
— Modification : formulaire de mise à jour des informations.
— Suppression : confirmation explicite avant suppression (pas de suppression acciden-
telle).
b) Entité métier principale — CRUD complet :
— Idem pour la seconde entité définie en Partie 1.
— Les données affichées doivent être filtrées et paginées.
— Les formulaires doivent inclure une validation serveur.
c) Optimisation des accès à la base de données :
— Ne récupérer que les colonnes nécessaires (SELECT champ1, champ2 plutôt que
SELECT *).
— Paginer tous les résultats (LIMIT / OFFSET).
— Ajouter des index sur les colonnes fréquemment interrogées.
— Limiter les jointures imbriquées et les N+1 queries.
— Utiliser un système de cache simple si pertinent (ex. : mise en cache des résultats de
recherche fréquents).
d) Sécurité minimale requise :
— Protection contre les injections SQL (requêtes paramétrées).
— Hashage des mots de passe (bcrypt ou argon2).
— Authentification par session ou JWT selon la stack choisie.
— Vérification des droits avant toute action sensible.
e) Architecture sobre :
— Pas de dépendances inutiles dans package.json / requirements.txt.
— Routes clairement séparées (utilisateurs, entité métier, auth).
— Gestion explicite des erreurs (codes HTTP appropriés).
Concepts Clés Green IT
Indicateurs Green IT à surveiller pour le back-end :
— Temps de réponse API : < 200 ms pour les opérations CRUD simples.
— Nombre de dépendances : minimiser — chaque paquet a un coût.
— Taille du bundle déployé : ne pas inclure les devDependencies en production.
— Nombre de requêtes BDD par page : viser < 5 requêtes par vue.

Étape 4.3 — Déploiement du site web
Approche Recommandée
Objectif : Rendre le site accessible en ligne via un hébergement gratuit et sobre. Le déploiement
doit être documenté et reproductible.
Plateformes recommandées :
— Vercel (https://vercel.com) — idéal pour les projets Node.js, Next.js, React, Vue.
— Render (https://render.com) — supporte Python, Node, bases de données PostgreSQL
gratuites.
— Railway (https://railway.app) — adapté aux projets full-stack avec base de données.
— GitHub Pages — pour les projets purement statiques.
— Fly.io — pour des conteneurs Docker légers.
Ressource vidéo utile :
— Déploiement Vercel : https://www.youtube.com/watch?v=2yXb5lhGaC4
Consignes
Consignes de déploiement :
a) Le site doit être accessible via une URL publique fonctionnelle au moment de la présentation.
b) Le fichier README.md doit contenir l’URL de déploiement.
c) Les variables d’environnement sensibles (mots de passe BDD, clés API) ne doivent jamais
apparaître dans le dépôt Git (utiliser .env listé dans .gitignore).
d) Le déploiement doit être automatisé depuis la branche main (CI/CD simple via GitHub
Actions ou la plateforme choisie).

Conclusion
Contexte
Cette seconde partie marque le passage de la réflexion à la réalisation. Elle vous demande de
produire un site web réel, sobre et fonctionnel, en assumant pleinement les choix documentés
lors de la Partie 1.
Un bon projet Green IT ne se résume pas à l’obtention d’un score EcoIndex élevé : c’est avant
tout un projet dans lequel chaque décision technique est justifiée, chaque fonctionnalité est
utile, et chaque ressource chargée est nécessaire.
La qualité de votre démarche sera évaluée autant que le résultat final. Un projet simple, bien
mené, rigoureusement documenté et honnêtement analysé vaut toujours plus qu’un projet
ambitieux, surchargé et peu maîtrisé.
« La perfection est atteinte non pas lorsqu’il n’y a plus rien à ajouter, mais lorsqu’il n’y a plus rien à
retirer. »
— Antoine de Saint-Exupéry
Bonne réalisation à toutes les équipes.
